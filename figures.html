前言

  • 图 0-1　全书二十一种模式全景——四个 subgraph 对应四部分，实线标出主干阅读顺序（核心模式依次递进，多智能体通向高级架构，RAG 为守护栏的前置知识）。

第1章 提示链

  • 图 1-1　提示链的执行结构——每个步骤单一职责，步骤之间隔着结构校验门；校验失败带错误反馈重试，重试预算耗尽即走 fail-fast 失败路径，绝不把未校验的中间结果传给下游。

第2章 路由

  • 图 2-1　入口路由的决策结构与兜底出口——低置信度与解析失败一律升舱到强模型，路由器只分诊、不处理，决策逻辑集中在这一处。
  • 图 2-2　一次路由的时序视图——高置信请求走语义支路，低置信请求 fail-open 升舱到兜底通道；路由器全程只分诊、不处理。

第3章 并行化

  • 图 3-1　并行化的三阶段结构——切分前验证"真独立"，执行时单路失败只影响自己，join 点显式实现 quorum 语义：缺席的路不允许被静默当作已评审。
  • 图 3-2　单个并行子任务的状态机——失败只滞留该路自己；join 点按 quorum 收束，允许"带缺席"汇合而不静默充数。

第4章 反思

  • 图 4-1　反思循环的最小闭环——批评驱动修订，多重停止闸门兜底（硬闸：最大轮数与成本预算；软闸：评审通过与分数收敛）
  • 图 4-2　反思循环的状态视角——草稿在"评审中/修订中"之间回环；把系统送出循环的只有软闸（通过或分数收敛）与硬闸（轮数与预算）。

第6章 规划

第8章 记忆管理

第9章 学习与适应

  • 图 9-1　学习闭环的骨架（捕获-工件化-复用-修正）与强化版进化环（生成-评估-选择-变异）。
  • 图 9-2　技能工件的状态机——候选技能先过验证器把关，验证失败退回候选，入库后靠复用效果升降级，被取代即弃用。

第10章 模型上下文协议

  • 图 10-1　MCP 的宿主-客户端-服务器三层架构——宿主为每个服务器维护一个客户端，服务器各自对接数据源，能力实现一次、全宿主复用。
  • 图 10-3　一次完整的 MCP 会话时序——initialize 协商、tools/list 动态发现、tools/call 受控调用，结果与错误都按协议回传。
  • 图 10-2　一次 MCP 工具调用的"两道翻译"——发现时工具定义翻译为 function calling schema，执行时模型调用翻译为 JSON-RPC 请求、结果再翻译回来。

第11章 目标设定与监控

  • 图 11-1　目标-进度-偏差反馈环——判定用原始目标而非执行中的转述；修正回到执行，违规与预算耗尽走停车出口。
  • 图 11-2　检查循环下任务的状态机——执行与比对交替推进，偏差走修正回到执行，判据达成正常退出，违规或预算耗尽即停车升级。

第12章 异常处理与恢复

  • 图 12-1　错误分类驱动的重试-熔断-降级状态机——瞬时错误重试，重试穷尽触发熔断统计，熔断打开期以降级维持服务，半开探测成功后回到主路径。
  • 图 12-3　调用方视角的失败处理时序——超时即退避，退避后重试直至成功；连错越限则熔断走降级，半开探测成功才恢复主路径。

第13章 人在回路

  • 图 13-1　置信度分级路由与人工审批闸门——高置信自动通过、中置信放行加抽检、低置信挂起转人工，裁决后从断点恢复，全链路审计留痕。
  • 图 13-2　一次自动执行与一次升级审批的调用时序——双阈值把高置信请求留在自动通道，低置信请求挂起转人工；裁决结构化返回，断点恢复后全链路留痕。

第14章 知识检索

  • 图 14-1　两段式 RAG 管道——离线建库与在线检索生成解耦；在线侧双路召回求全、重排求精，相关性低于阈值走拒答而非硬答。
  • 图 14-2　在线检索生成的调用时序——两路召回求全、RRF 融合、重排器精排、生成器带引用作答；重排分低于阈值时由拒答通道接管而非硬答。

第15章 智能体间通信

  • 图 15-1　两个 agent 经 A2A 协作的全流程——客户端凭 Agent Card 发现能力并发起任务，远端以状态机推进生命周期，input-required 挂起与产物回传是协议的一等公民。
  • 图 15-2　A2A Task 状态机——submitted 到 working 是受理确认，input-required 把"挂起等人类"做成协议一等状态，completed/failed/canceled 三个终态各有产物、原因与取消语义。

第16章 资源感知优化

  • 图 16-1　资源感知级联的骨架——查询先过缓存，mini 档先答并以"自评置信度 + 机械校验"把关，不达标才升级 frontier，每条路径都写进成本账本。
  • 图 16-2　模型分级的选型象限——横轴是任务复杂度、纵轴是单次价值：低复杂低价值交给 mini 档，高复杂高价值才付 frontier 的钱，"简单但错不起"与"常规推理"落在 standard 档；级联（16.1.2）就是沿横轴向右逐级升档的运行时形态。

第17章 推理技术

  • 图 17-1　系统 1 / 系统 2 与测试时算力分配——难度决定走一步作答还是显式推理，投票的一致与分歧决定"再想多少"；算力沿"一步作答 → 多链投票 → 推理模型"逐级上调，收益边际递减，故按难度分配而非无脑拉满。
  • 图 17-2　典型 agent 工作负载的算力/成本分配示例（示例口径，随任务形态浮动）——深度推理虽只服务少数困难请求，却能占去近三分之一预算，这正是"按难度分配测试时算力"的经济动机；检索与工具执行是常被低估的固定开销。

第18章 护栏机制

  • 图 18-2　一次被拦与一次放行的调用时序——输入闸按注入特征 fail-closed 拦截可疑内容，干净内容经模型、输出闸结构校验后才允许触达工具；拦截是留痕的正常错误，不是崩溃。

第19章 评估与监控

  • 图 19-1　评估金字塔与离线-在线双回路——在线发现的坏案例单向回流黄金集，是评估体系自我进化的关键一环。
  • 图 19-2　LLM 裁判的消偏流水线——断言先行省钱，换序消位置偏差，人工抽检给裁判做实时体检。
  • 图 19-3　离线评估与 CI 门禁的交互时序——断言先行省钱、黄金集回归判优劣，低于相对基线即打回；边缘失败可标记例外并强制人工审批，但例外必须留痕，不能静默累积成常态。

第20章 优先级排序

  • 图 20-1　优先级队列与波间动态重排——抢占只发生在波与波之间，执行中的任务不被打断。
  • 图 20-2　优先级调度下的任务状态机——抢占只发生在波与波之间（被抢占的状态先回存再重排队，执行中的任务不被打断）；重排队后既可能再次胜出，也可能因预算耗尽转入降级阶梯。

第21章 探索与发现

  • 图 21-1　假设-实验-证伪-知识入库的发现环——生成与验证隔离，证伪记录与冠军共同构成下一轮的母本与先验。
  • 图 21-3　假设-证伪-变异-入库的交互时序——生成与验证隔离、判据预注册，证伪不是浪费而是先验；只有通过留出集复验的候选才配更新冠军并入库。
  • 图 21-2　验证闸门的四级强度阶梯——越靠后越接近"担保"，对外宣称的发现至少要走到第四级。
